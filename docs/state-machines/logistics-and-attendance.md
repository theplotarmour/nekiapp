# Shipment and attendance contracts

**Status:** P0 review draft, NK-DOC-3.03. Sources: TDD §6.4/6.5/15, model §4.6, flows F2/F3/F9, plan P4/P5. [Shared rules](README.md), D7 and [contribution contracts](contributions.md) apply. Actor capabilities, added states/metadata, events and errors are proposed pending G25/schema/API review. Every row requires expected version, idempotency and atomic history/audit/outbox; errors inherit shared defaults.

## Shipment

Proposed resolution of G14: physical lifecycle remains CREATED, UNASSIGNED, VOLUNTEER_ASSIGNED, PICKUP_READY, PICKED_UP, IN_TRANSIT, ARRIVED, DELIVERED, VERIFIED, CANCELLED. DELAYED, RESCHEDULED and ISSUE_REPORTED become orthogonal incident/schedule metadata and events, not physical-state replacements. Existing enum values remain historical until the schema is reconciled. Delay cannot turn delivered items back into a moving shipment. “Current assignee” always means current server assignment revision and current D7 approval, not a cached user role.

Pre-pickup states are exactly CREATED, UNASSIGNED, VOLUNTEER_ASSIGNED, PICKUP_READY. Nonterminal physical states also include PICKED_UP, IN_TRANSIT, ARRIVED; exclude DELIVERED/VERIFIED/CANCELLED for S12. S15 does not complete a return by itself: LD-01 must define final disposition and contribution recovery without calling returned items donated. S16 uses a drop-off fulfilment record represented as shipment with explicit mode; decide that modelling choice under LD-01 before DDL.

Offline commands carry stable command ID, expected shipment and assignment revisions, captured timestamp and local media references. They display Pending sync until accepted. Out-of-order/conflicting actions are rejected with authorized current state; no client blindly retries with a refreshed version. Rejected custody evidence can enter a scoped ops case instead of being silently lost. Finance commands never join this queue.

## Attendance and booking

Proposed G14 resolution: REMINDED is delivery metadata, not an assignment state. Check-in works for confirmed bookings even if all reminders fail. Proposed waitlist offers are separate records with expiry/reserved capacity; they are not confirmed volunteering or verified hours. The existing mandatory `assignment.contribution_id` conflicts with waitlist-before-contribution: use a separate booking-request identity and create contribution/confirmed assignment atomically on acceptance (LD-03).

All rows also advance aggregate version. No-show correction never grants historical check-in or exact location to an unrelated actor. Duration is stored in integer seconds with explicit reviewed display rounding, capped to allowed interval/slot unless a separately approved policy changes it. GPS spoof flags are review signals, not automatic misconduct findings.
