## Code evidence and implications

**A:** [Post controller](https://github.com/parrottkim/flutter_riverpod_clean_architecture/blob/c729fddfff6fe3c34b70c6b31a3b76e30efd105f/lib/src/presentation/controller/post/post_controller.dart) uses `posts.last` during initial loading and tracks loading/end state for later pages. NEKI must explicitly represent empty initial pages and recoverable pagination errors. [Domain use cases](https://github.com/parrottkim/flutter_riverpod_clean_architecture/blob/c729fddfff6fe3c34b70c6b31a3b76e30efd105f/lib/src/domain/usecase/post/post_usecase.dart) use provider annotations/ref directly; keep NEKI business rules independently testable instead of copying this dependency direction.

**B:** [Repository](https://github.com/guilherme-v/flutter-clean-architecture-example/blob/9d506dcf58c74868bd04eb894efff0ee976b6227/lib/layers/data/character_repository_impl.dart) and [local storage](https://github.com/guilherme-v/flutter-clean-architecture-example/blob/9d506dcf58c74868bd04eb894efff0ee976b6227/lib/layers/data/source/local/local_storage.dart) show the cache algorithm directly. NEKI needs scoped keys, expiry, logout clearing and explicit stale state. This repository supports a qualitative controller comparison; it does not establish the previous ADR-002 claim of a 1.6× BLoC code-volume penalty.

**C:** [Auth notifier](https://github.com/Uuttssaavv/flutter-clean-architecture-riverpod/blob/045b52ce6859e4ce8585eb2baf5d794c78fb320a/lib/features/authentication/presentation/providers/state/auth_notifier.dart) distinguishes successful remote authentication from failed local persistence. [Dashboard notifier](https://github.com/Uuttssaavv/flutter-clean-architecture-riverpod/blob/045b52ce6859e4ce8585eb2baf5d794c78fb320a/lib/features/dashboard/presentation/providers/state/dashboard_notifier.dart) appends pages and exposes reset. NEKI needs query-generation isolation so a stale search response cannot populate a newer query; no such guarantee is inferred from state-library choice.

**D:** [Dio helper](https://github.com/MohammadFayyad/flutter-ecommerce-app/blob/b12769af973f3a44cf7a2ab3fa9c7073c2c0fcd2/lib/core/networking/dio_helper.dart) enables request header/body logging and accepts POST options without forwarding them. [Cart Cubit](https://github.com/MohammadFayyad/flutter-ecommerce-app/blob/b12769af973f3a44cf7a2ab3fa9c7073c2c0fcd2/lib/features/my_cart/cubit/cart_cubit.dart) accesses product index zero on success. These are concrete reasons to implement NEKI's redacted transport and empty/error states independently; no upstream runtime exploit is claimed.

**E:** [Order repository](https://github.com/Sameera-Perera/Flutter-TDD-Clean-Architecture-E-Commerce-App/blob/0c7169af7a907a1c771b4ac8e45b41695976f4af/lib/features/orders/data/repositories/order_repository_impl.dart) separates online creation from local reads. [Tests](https://github.com/Sameera-Perera/Flutter-TDD-Clean-Architecture-E-Commerce-App/blob/0c7169af7a907a1c771b4ac8e45b41695976f4af/test/features/orders/data/repositories/order_repository_impl_test.dart) demonstrate mock boundaries, not successful reconciliation against a backend. NEKI acceptance must cover uncertain outcomes, idempotency and authoritative server receipts.

**F:** [Order creation](https://github.com/mahmoodhamdi/TStore/blob/129431026dfb564fd8cd9186aed5b3109533937b/lib/features/orders/data/repositories/order_repository_impl.dart) calculates totals from client item prices before inserting an order. NEKI's reviewed server quote and append-only financial facts remain authoritative. [Chat repository](https://github.com/mahmoodhamdi/TStore/blob/129431026dfb564fd8cd9186aed5b3109533937b/lib/features/chat/data/repositories/chat_repository_impl.dart) shows a realtime subscription; its existence does not prove revocation, sequence recovery or resource cleanup for NEKI tracking.

**G:** [Database service](https://github.com/kforjan/delivery-app/blob/8f3a59454204f9b3d65a041ab9ba7605ae4f26cd/lib/services/database.dart) reconstructs an order when changing location/status. [Tracking page](https://github.com/kforjan/delivery-app/blob/8f3a59454204f9b3d65a041ab9ba7605ae4f26cd/lib/app/home/order/tracking_page.dart) listens to its document and logs coordinates. NEKI instead requires assignment-scoped access, ordered samples, expiry, disclosure precision and audited custody transitions.

**H:** [Tracking rider](https://github.com/patriciaperez90/flutter-food-delivery-app-clone/blob/e7bb99302b6fc52a263de74a770fff47141a766f/enatega-multivendor-app/src/components/OrderDetail/TrackingRider/TrackingRider.js) combines a network query and subscription with cleanup; [rider task](https://github.com/patriciaperez90/flutter-food-delivery-app-clone/blob/e7bb99302b6fc52a263de74a770fff47141a766f/enatega-multivendor-rider/src/utilities/location.js) sends the latest location by mutation. These are frontend patterns only. NEKI still needs gap detection and snapshot reconciliation; background tracking must not silently replace the approved foreground MVP behavior.

Keep ADR-002's accepted Riverpod direction, but remove its unsupported numerical comparison. Do not change state framework based on these examples. Next execute an isolated NEKI compatibility spike with pinned Flutter/Dart, Riverpod/codegen, Freezed, networking, navigation and Drift/web; test empty/error pagination, stale search response, disposal, logout clearing and queued-action reconciliation. Versions from unrelated applications cannot substitute for that spike.

## Reproduction

For each manifest row, clone its URL into the corresponding A–H research directory and check out the exact commit. A shallow clone may need an explicit fetch of that commit. Do not execute repository setup scripts to reproduce this static review. Then run:

```powershell
.venv-contracts/Scripts/python tools/verify_rnd_sources.py D:/Code/neki-research
```

The verifier checks revision identity, Git-blob hashes, license-file inventory and test-file inventory. It does not validate the correctness of this interpretation or execute upstream tests.
